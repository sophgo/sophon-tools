## 1 安全

### 1.1 通用安全

#### 事项说明

在操作、安装本设备时，请遵循设备标识以及手册中说明的通用安全相关注意事项。

关于手册中提及的"危险"、"警告"、"注意"事项，只是对安全事项的补充，并不代表所有安全事项。

#### 安装要求

操作、安装、维护本设备的人员必须了解所有安全注意事项，并掌握正确的操作方法后才可进行操作。关于安装要求做以下几点说明：

- 设备操作、安装、维护必须由经过培训的人员完成。
- 设备检修必须由本公司授权人员完成。
- 设备部件更换必须由本公司授权人员完成。
- 设备因安装导致的设备故障、异常需由操作人员及时与我司联系。

#### 接地要求

设备安装前需要先完成接地操作，设备拆除时最后拆除地线。

- 严禁在设备未接地或接地不良的情况下对设备进行任何操作。
- 操作设备前请进行接地检查，确保设备接地良好。

#### 人身安全

- 设备安装、操作前，需要身穿防静电服，佩戴防静电手套或手环，摘除手部导电饰品，避免引起短路被电击损伤。
- 严禁在危险环境下操作、安装设备，如雷雨天气、易燃环境等。

#### 设备安全

保证设备在任何一种安装方式下的牢固可靠，如桌放、挂墙或机架安装。

- 保证设备在任何一种安装方式下的牢固可靠，如桌放、挂墙或机架安装。
- 对设备进行开机操作前确保接地良好，关机操作完成后再拆除地线。
- 维护窗操作需要佩戴防静电手套，拆卸或安装维护窗盖板请使用螺丝刀。
- 严禁遮挡、堵塞设备通风面板。
- 严禁拔除设备密封胶塞，如天线胶塞等。

### 1.2 电气安全

#### 恶劣环境

严禁在雷雨天气下对设备进行交流电操作，否则会有致命危险。

严禁在雷雨天气下对设备进行室外设备箱体、抱杆等作业，否则会有致命危险。

- 严禁在雷雨天气下对设备进行室外设备箱体、抱杆等作业，否则会有致命危险。
- 严禁在高压电源供电情况下，不规范地进行操作，否则会有致命危险。

#### 设备电源

严禁在设备上电状态下，进行带电拆除电源线操作，避免产生电火花导致身体损伤。

- 进行拆除设备电源线操作前，必须优先关闭电源使设备处于已关机状态下。
- 进行设备电源线连接设备操作前，必须优先确认电源线正负极标识正确再进行连接。
- 确保设备电源线与设备相连后，连接位置牢固不松动。

#### 静电

为防止人体摩擦、移动产生的静电损坏设备，对设备操作前，先进行静电放电操作。

- 触摸、手持设备前，必须佩戴防静电手环，并将手环的接地端子接地。

## 2 产品简介

### 2.1 产品概述

算丰微服务器 SE8-S1 是面向深度学习推理的高密度算力服务器，搭载算丰第四代智能视觉深度学习处理器 BM1684X，国产 X86 强劲主控加持，大算力、低能耗、小体积，支持混合精度计算，承载丰富的算法应用，可灵活应对公安、交通、园区、生产、仓储、教育等大并发业务场景，为千行百业智慧赋能。

### 2.2 产品特点

#### 强劲主控，超高算力，超强解码，增强编码

- 主控节点采用国产 X86：3.0GHz，8 核 16 线程，L3 16MB，默认配备 2 条 32G 内存，1TB SSD 系统盘
- 支持 96、192、288 路 1080P 高清视频智能分析
- 支持 96、192、288 路 1080P 高清视频全流程处理
- 支持 96、192、288 路 1080P 高清视频硬件解码与 36、72、108 路编码

#### 接口与部署

- 业务网络接口：2 个 10M/100M/1000M 自适应以太网口
- 其他接口：1 个 RJ45 BMC 管理网口，1 个 USB-C 主控调试串口，1 个 HDMI 接口，4 个 USB 3.0 接口，4 个 2.5 寸 SATA 盘位（选配）
- 支持 0°C 至 +45°C 工作环境
- 便携式服务器，体积小巧，乐高式拼接上架，支持独立或组合部署

#### 高可靠性，加密保护

- 高容量 eMMC 可开发支持主备分区。
- 支持异常类故障告警与保护处理机制。
- 支持可编程加密用于隐私信息保护。

#### 易用工具链，灵活开发

- Sophon SDK 一站式深度学习开发工具包。
- 支持 Caffe/Darknet/TensorFlow/PyTorch/MXNet/PaddlePaddle/ONNX 等主流深度学习框架。
- 支持分类、检测主流网络模型，支持自定义算子开发。
- 支持 Docker 容器化，算法应用快速部署。

### 4.2 设备操作

#### 4.2.1 下电

SE8-S1 支持以下三种下电方式。

**方式一 操作系统界面下电**

上电状态下：

步骤 1 连接显示器和键盘、鼠标后，在操作系统界面内关机，系统整机进入下电流程，约 2s 后系统整机完成下电

- 步骤 2 观察电源指示灯（绿色）熄灭，表示 SE8-S1 下电成功

- 结束

**方式二 PWR 摁键下电**

上电状态下：

- 步骤 1 在上电状态下短摁前面板 PWR 按键

步骤 2 观察电源指示灯（绿色）熄灭，表示 SE8-S1 下电成功，若有接显示器，需要在系统中点击确认 power off

- 结束

**方式三 电源线缆下电**

- 步骤 1 拔掉电源线缆，将 SE8-S1 下电

- 步骤 2 观察电源指示灯（绿色）熄灭，表示 SE8-S1 下电成功

- 结束

**注意**

使用方式二下电后，再次上电需要重新插拔电源线缆。

#### 4.2.2 上电

SE8-S1 支持以下两种上电方式。

**方式一 插入电源线上电**

- 步骤 1 插入电源线缆，SE8-S1 自动上电

- 步骤 2 电源指示灯呈现绿色常亮状态，SE8-S1 上电成功

- 结束

### 5.2 系统端口映射

SE8-S1 默认会通过主控节点（控制板）为所有的算力节点（核心板）映射 22 端口，以方便用户通过 SSH 连接访问算力节点。

默认情况下，为大算力板（6个算力节点）映射的端口号为：20021~20026；为小算力板（3个算力节点）映射的端口号为：10024~10026。

## 说明

- 若用户终端IP为192.168.1.110，SE8-S1的网卡enp4s0f0的IP为192.168.1.107，则用户可以通过`ssh -p 40023 linaro@192.168.1.107`方式，从用户终端登录到大算力板的第3块核心板上。

核心板的IP是由控制板通过在开机前设置给核心板的：iptable_setup.sh脚本会在SE8-S1开机时自动执行，获取GE1口IP，并配置端口映射。若GE1口IP在开机时获取失败，则会导致端口映射不成功，需等到GE1口IP获取成功后再执行一次。

### 5.4 网口聚合配置

SE8-S1对外提供了2个千兆自适应网口，在满载情况下需要配置GE1和GE2为网口聚合模式以确保满足网络带宽需求。

网口聚合就是把多张物理网卡通过软件虚拟成一个网卡，被聚合的物理网卡使用逻辑上的同一个IP和MAC地址，实现端口汇聚，扩容链路带宽。

**注意**

有的网口聚合需要路由器或交换机支持并做相应的配置。

**网口聚合的7种模式**

| 模式 | 描述 | 说明 |
|------|------|------|
| balance-rr | 平衡轮循环策略 | • 链路负载均衡，增加带宽，支持容错，一条链路故障会自动切换正常链路。<br>• 传输数据包顺序是依次传输（即：第1个包走eth0，下一个包就走eth1...一直循环下去，直到最后一个传输完毕），此模式提供负载平衡和容错能力；但客户端很有可能会出现数据包无序到达的问题，而无序到达的数据包会被要求重新发送，网络吞吐量会下降。 |
| active-backup | 主备份策略 | • 主备模式，只有一块网卡active，另一块备用standby，所有流量都在active链路上处理。<br>• 此模式只提供了容错能力；提供高网络连接的可用性，但资源利用率较低，只有一个接口处于工作状态。 |
| balance-xor | 平衡策略 | • XOR Hash负载分担，和交换机的聚合强制不协商方式配合。<br>• 基于指定的传输HASH策略传输数据包。缺省的策略是：(源MAC地址XOR目标MAC地址)% slave数量。其他的传输策略可以通过xmit_hash_policy选项指定，此模式提供负载平衡和容错能力。 |
| broadcast | 广播策略 | • 所有包从所有网络接口发出，这个不均衡，只有冗余机制，但过于浪费资源。此模式适用于金融行业，因为需要高可靠性的网络，不允许出现任何问题。需要和交换机的聚合强制不协商方式配合。<br>• 在每个slave接口上传输每个数据包，此模式提供了容错能力。 |
| 802.3ad | IEEE 802.3ad动态链接聚合 | • 802.3ad协议，和交换机的聚合LACP方式配合（需要xmit_hash_policy）。标准要求：所有设备在聚合操作时，要在同样的速率和双工模式，而且，和除了balance-rr模式外的其它bonding负载均衡模式一样，任何连接都不能使用多于一个接口的带宽。<br>• 创建一个聚合组，它们共享同样的速率和双工设定。根据802.3ad规范将多个slave工作在同一个激活的聚合体下。<br>• 必要条件：①ethtool支持获取每个slave的速率和双工设定；②switch(交换机)支持IEEE 802.3ad Dynamic link aggregation；③大多数switch(交换机)需要经过特定配置才能支持802.3ad模式 |
| balance-tbb | 适配器传输负载均衡 | • 根据每个slave的负载情况选择slave进行发送，接收时使用当前轮到的slave。该模式要求slave接口的网络设备驱动有某种ethtool支持；而且ARP监控不可用。<br>• 不需要任何特别的switch(交换机)支持的通道bonding。在每个slave上根据当前的负载（根据速度计算）分配外出流量。如果正在接受数据的slave出故障了，另一个slave接管失败的slave的MAC地址。<br>• 必要条件：ethtool支持获取每个slave的速率 |
| balance-alb | 适配器适应性负载均衡 | • tbb基础上增加了rlb(接收负载均衡receive load balance)。不需要任何switch(交换机)的支持。接收负载均衡是通过ARP协商实现的。<br>• 该模式包含了balance-tbb模式，同时加上针对IPV4流量的接收负载均衡(receive load balance, rlb)，而且不需要任何switch(交换机)的支持。接收负载均衡是通过ARP协商实现的。bonding驱动截获本机发送的ARP应答，并把源硬件地址改写为bond中某个slave的唯一硬件地址，从而使得不同的对端使用不同的硬件地址进行通信。 |

SE8-S1配置enp4s0f0(GE1)和enp4s0f1(GE2) bonding模式为balance-rr的方式如下：登录控制板，修改网络配置文件，示例如下：

```
se8@SE8-S1-host:~# sudo vim /etc/netplan/01-network-manager-all.yaml
# Let NetworkManager manage all devices on this system
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    enp4s0f0:
      dhcp4: no
    enp4s0f1:
      dhcp4: no
    enp2s0f0:
      dhcp4: no
      addresses: [172.16.140.200/24]
    nameservers:
      addresses: []
    optional: yes
    enp2s0f1:
      dhcp4: no
    addresses: [172.16.140.201/24]
```

应用生效：

修改parameters: mode: balance-rr配置模式；ifconfig bond0 down卸载虚拟网卡，然后使用rmmod bonding卸载模块；最后就可以通过netplan apply使修改应用生效。

**注意**

- 配置聚合模式后，需要修改`/root/se_ctrl/iptable_setup.sh`的`wanname=$(ifconfig | grep enp | awk -F: 'NR==1{print $1}')`为bond网口的名。

- 修改控制板GE1口（enp4s0f0）IP，不会自动做端口映射，需用户手动执行`/root/se_ctrl/iptable_setup.sh`进行端口映射。
- 算力核心板的IP是由控制板在开机过程中设置的，如果单独修改了控制板GE1或GE2的IP，必须执行`reboot_all`命令重启整机，否则会导致核心板无法连通、端口映射异常。

### 6.3 内存空间分配

**说明**

- SE8-S1 控制板上默认配备 2 条 32GB DDR4 内存。

- SE8-S1 算力核心板上内存采用 LPDDR4x，每个算力核心板使用 4 颗 4GB DDR 颗粒，总容量为 16GB。默认情况下，内存空间分配情况为，系统内存：6.9GB，TPU：2.5G，VPU：3GB，VPP：3GB。用户可参照 SoC 模式下内存空间分配的修改方式和工具来自定义修改。

### 7.3 控制板给算力核心板执行脚本

控制板/root/se_ctrl/script 目录下提供了 core_run_command_bynet.sh 脚本方便客户快速获取算力核心板信息以及执行命令。

使用帮助:

```
./core_run_command_bynet.sh "shell command" username passwd [id]
```

```
./core_run_command_bynet.sh "/bm_bin/bm_version" linaro linaro
```

```
./core_run_command_bynet.sh "/bm_bin/bm_version" linaro linaro 4
```

**说明**

- 如果没指定 id，会对所有算力板执行"shell command"命令
- shell command 支持连续命令，使用"选择"按钮即可。

例如，如果想实现拷贝功能可以使用如下命令：

```
./core_run_command_bynet.sh "~/script/scp_file2dir_local.exp 192.168.1.107 linaro linaro ~/ test ~/" linaro linaro
```

其中：
- 192.168.1.107 为控制板 GE1 口 IP
- 引号里的 linaro linaro 为控制板的用户名和密码
- ~/test 为控制板上的文件源路径
- ~/ 为拷贝到算力核心板上的目的路径
