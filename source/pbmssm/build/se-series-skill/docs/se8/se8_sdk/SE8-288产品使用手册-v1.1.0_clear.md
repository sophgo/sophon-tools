## 1 安全

### 1.1 通用安全

#### 事项说明

在操作、安装本设备时，请遵循设备标识以及手册中说明的通用安全相关注意事项。

关于手册中提及的"危险"、"警告"、"注意"事项，只是对安全事项的补充，并不代表所有安全事项。

#### 安装要求

操作、安装、维护本设备的人员必须了解所有安全注意事项，并掌握正确的操作方法后才可进行操作。关于安装要求做以下几点说明：

- 设备操作、安装、维护必须由经过培训的人员完成。
- 设备检修必须由本公司授权人员完成。
- 设备部件更换必须由本公司授权人员完成。

设备因安装导致的设备故障、异常需由操作人员及时与我司联系。

#### 接地要求

- 设备安装前需要先完成接地操作，设备拆除时最后拆除地线。
- 严禁在设备未接地或接地不良的情况下对设备进行任何操作。
- 操作设备前请进行接地检查，确保设备接地良好。

#### 人身安全

- 设备安装、操作前，需要身穿防静电服，佩戴防静电手套或手环，摘除手部导电饰品，避免引起短路被电击损伤。
- 严禁在危险环境下操作、安装设备，如雷雨天气、易燃环境等。

#### 设备安全

- 保证设备在任何一种安装方式下的牢固可靠，如桌放、挂墙或机架安装。
- 对设备进行开机操作前确保接地良好，关机操作完成后再拆除地线。
- 维护窗操作需要佩戴防静电手套，拆卸或安装维护窗盖板请使用螺丝刀。
- 严禁遮挡、堵塞设备通风面板。
- 严禁拔除设备密封胶塞，如天线胶塞等。

### 1.2 电气安全

#### 恶劣环境

- 严禁在雷雨天气下对设备进行交流电操作，否则会有致命危险。
- 严禁在雷雨天气下对设备进行室外设备箱体、抱杆等作业，否则会有致命危险。
- 严禁在高压电源供电情况下，不规范地进行操作，否则会有致命危险。

#### 设备电源

- 严禁在设备上电状态下，进行带电拆除电源线操作，避免产生电火花导致身体损伤。
- 进行拆除设备电源线操作前，必须优先关闭电源使设备处于已关机状态下。
- 进行设备电源线连接设备操作前，必须优先确认电源线正负极标识正确再进行连接。
- 确保设备电源线与设备相连后，连接位置牢固不松动。

#### 静电

- 为防止人体摩擦、移动产生的静电损坏设备，对设备操作前，先进行静电放电操作。
- 触摸、手持设备前，必须佩戴防静电手环，并将手环的接地端子接地。

## 2 产品简介

### 2.1 产品概述

算丰微服务器 SE8 288-EA6-72（以下简称 SE8-288）是面向深度学习推理的高密度算力服务器，搭载算丰第四代智能视觉深度学习处理器 BM1684X，国产 X86 强劲主控加持，大算力、低能耗、小体积，支持混合精度计算，承载丰富的算法应用，可灵活应对公安、交通、园区、生产、仓储等大并发业务场景，为千行百业智慧赋能。

### 2.2 产品特点

#### 强劲主控，超高算力，超强解码，增强编码

- 主控节点采用国产 X86：2.8GHz，8 核 16 线程，L3 16MB，默认配备 2 条 32G 内存，1TB SSD 系统盘
- 最高支持 288 路 1080P 高清视频智能分析
- 最高支持 288 路 1080P 高清视频全流程处理
- 最高支持 288 路 1080P 高清视频硬件解码与 108 路编码

#### 接口与部署

- 业务网络接口：2 个 10M/100M/1000M 自适应以太网口
- 其他接口：1 个 RJ45 BMC 管理网口，1 个 RJ45 主控调试串口，1 个 HDMI 接口，4 个 USB 3.0 接口
- 支持 0°C 至 +40°C 工作环境
- 便携式服务器，体积小巧，乐高式拼接上架，支持独立或组合部署

#### 高可靠性，加密保护

- 高容量 eMMC 可开发支持主备分区。
- 支持异常类故障告警与保护处理机制。
- 支持可编程加密用于隐私信息保护。

#### 易用工具链，灵活开发

- Sophon SDK 一站式深度学习开发工具包。
- 支持 Caffe/Darknet/TensorFlow/PyTorch/MXNet/PaddlePaddle/ONNX 等主流深度学习框架。
- 支持分类、检测主流网络模型，支持自定义算子开发。
- 支持 Docker 容器化，算法应用快速部署。

### 4.2 设备操作

#### 4.2.1 下电

SE8-288 支持以下两种下电方式。

**方式一 操作系统界面下电**

上电状态下：

步骤 1 连接显示器和键盘、鼠标后，在操作系统界面内关机，系统整机进入下电流程，约 2s 后系统整机完成下电

• 步骤 2 观察电源指示灯（红色）熄灭，表示 SE8-288 下电成功

• 结束

**注意**

使用该方式下电后，再次上电需要重新插拔电源线缆。

**方式二 电源线缆下电**

• 步骤 1 拔掉电源线缆，将 SE8-288 下电

• 步骤 2 观察电源指示灯（红色）熄灭，表示 SE8-288 下电成功

• 结束

#### 4.2.2 上电

• 步骤 1 插入电源线缆，SE8-288 自动上电

• 步骤 2 电源指示灯呈现红色常亮状态，SE8-288 上电成功

• 结束

## 5 初始化配置

### 5.1 网络拓扑

SE8-288 由一块控制板和两块算力板组成，控制板和算力板通过一块背板相连。大算力板由 6 块算力核心板组成，小算力板由 3 块算力核心板组成。算力核心板搭载算力自研智能视觉深度学习处理器 BM1684X，为算力节点；共 1 个主控节点和 9 个算力节点。

控制板搭载国产 X86 处理器，为主控节点，有:

2 个对外网卡：enp4s0f0（即 GE1）、enp4s0f1（即 GE2）；默认情况下，enp4s0f0（GE1）配置为 DHCP，enp4s0f1（GE2）配置为固定 IP 172.16.180.200。

4 个对内网卡：enp2s0f0、enp2s0f1、enp2s0f2、enp2s0f3。4 个对内网卡分为 2 组：enp2s0f0、enp2s0f1 为网段 A，IP 为 *.*.*.*.*.*.*.*.*.*.*.*。（前 3 个网段用户可以设置）；enp2s0f2、enp2s0f3 为网段 B，IP 为 *.*.*.*.*.*.*.*.*.*.*.*。（前 3 个网段用户可以设置）。

**说明**

- 两组对内网卡 enp2s0f0、enp2s0f1 和 enp2s0f2、enp2s0f3 不能在一个网段，即网段 A 和网段 B 不能相同。

默认情况下，enp2s0f0 为固定 IP 172.16.140.200、enp2s0f1 为固定 IP 172.16.140.201、enp2s0f2 为固定 IP 172.16.150.200、enp2s0f3 为固定 IP 172.16.150.201。

- enp2s0f0、enp2s0f1 与大算力板（6 节点算力板）在网段 A 局域网内，enp2s0f2、enp2s0f3 与小算力板（3 节点算力板）在网段 B 局域网内。

• 大算力板上 6 个算力节点的 IP 是***.*

eg: enp2s0f0 的 ip 为 172.16.140.200，enp2s0f1 的 ip 为 172.16.140.201。大算力板上的 6 个算力节点 IP 为 172.16.140.11 ~ 172.16.140.16。

• 小算力板上 3 个算力节点的 IP 是 *.$

eg: enp2s0f2 的 ip 为 172.16.150.200，enp2s0f3 的 ip 为 172.16.150.201。小算力板上的 3 个算力节点 IP 为 172.16.150.14 ~ 172.16.150.16。

**注意**

- 以上网卡名称为主控操作系统为 Ubuntu20.04 时的默认网卡名称；在不同操作系统（如麒麟等）下，网卡的名称可能会不同。

### 5.2 系统端口映射

SE8-288 默认会通过主控节点（控制板）为所有的算力节点（核心板）映射 22 端口，以方便用户通过 SSH 连接访问算力节点。

默认情况下，为大算力板（6个算力节点）映射的端口号为：20021~20026；为小算力板（3个算力节点）映射的端口号为：10024~10026。

## 说明

若用户终端 IP 为 192.168.1.110，SE8-288 的网卡 enp4s0f0 的 IP 为 192.168.1.107，则用户可以通过 `ssh -p 20023 linaro@192.168.1.107` 方式，从用户终端登录到大算力板的第 3 块核心板上。

核心板的 IP 是由控制板通过在开机前设置给核心板的：iptable_setup.sh 脚本会在 SE8-288 开机时自动执行，获取 GE1 口 IP，并配置端口映射。若 GE1 口 IP 在开机时获取失败，则会导致端口映射不成功，需等到 GE1 口 IP 获取成功后再执行一次。

### 5.3 算力核心板 IP 直连

算力核心板 IP 直连需要保证用户终端和 SE8-288 在一个局域网下（如果跨多个路由，需要在主路由配置路由映射）。在用户终端（如一台 Ubuntu PC 主机）上，执行命令 `route add -net 172.16.0.0 netmask 255.255.0.0 gw 192.168.1.107 dev enp0s31f6` 添加路由；其中，172.16.0.0 为 SE8-288 上 4 个对内网卡所在的网段，192.168.1.107 为用户终端 IP，enp0s31f6 为用户终端的网卡名称。示例如下：

| 0.0.0.0 | 172.28.9.1 | 0.0.0.0 | UG | 100 | 0 | 0 | enp0s31f6 |
| 169.254.0.0 | 0.0.0.0 | 255.255.0.0 | U | 1000 | 0 | 0 | br-e47aa907ba0c |
| 172.17.0.0 | 0.0.0.0 | 255.255.0.0 | U | 0 | 0 | 0 | docker0 |
| 172.18.0.0 | 0.0.0.0 | 255.255.0.0 | U | 0 | 0 | 0 | br-e47aa907ba0c |

`ssh linaro@172.16.140.11`

### 5.4 网口聚合配置

SE8-288 对外提供了 2 个千兆自适应网口，在满载情况下需要配置 GE1 和 GE2 为网口聚合模式以确保满足网络带宽需求。

网口聚合就是把多张物理网卡通过软件虚拟成一个网卡，被聚合的物理网卡使用逻辑上的同一个 IP 和 MAC 地址，实现端口汇聚，扩容链路带宽。

**注意**

有的网口聚合需要路由器或交换机支持并做相应的配置。

**网口聚合的 7 种模式**

| 模式 | 描述 | 说明 |
|------|------|------|
| balance-rr | 平衡轮循环策略 | • 链路负载均衡，增加带宽，支持容错，一条链路故障会自动切换正常链路。<br>• 传输数据包顺序是依次传输（即：第1个包走eth0，下一个包就走eth1……一直循环下去，直到最后一个传输完毕），此模式提供负载平衡和容错能力；但客户端很有可能会出现数据包无序到达的问题，而无序到达的数据包会被要求重新发送，网络吞吐量会下降。 |
| active-backup | 主备份策略 | • 主备模式，只有一块网卡active，另一块备用standby，所有流量都在active链路上处理。<br>• 此模式只提供了容错能力；提供高网络连接的可用性，但资源利用率较低，只有一个接口处于工作状态。 |
| balance-xor | 平衡策略 | • XOR Hash 负载分担，和交换机的聚合强制不协商方式配合。<br>• 基于指定的传输 HASH 策略传输数据包。缺省的策略是：(源 MAC 地址 XOR 目标 MAC 地址) % slave 数量。其他的传输策略可以通过 xmit_hash_policy 选项指定，此模式提供负载平衡和容错能力。 |
| broadcast | 广播策略 | • 所有包从所有网络接口发出，这个不均衡，只有冗余机制，但过于浪费资源。此模式适用于金融行业，因为需要高可靠性的网络，不允许出现任何问题。需要和交换机的聚合强制不协商方式配合。<br>• 在每个 slave 接口上传输每个数据包，此模式提供了容错能力。 |
| 802.3ad | IEEE 802.3ad 动态链接聚合 | • 802.3ad 协议，和交换机的聚合 LACP 方式配合（需要 xmit_hash_policy）。标准要求：所有设备在聚合操作时，要在同样的速率和双工模式，而且，和除了 balance-rr 模式外的其它 bonding 负载均衡模式一样，任何连接都不能使用多于一个接口的带宽。<br>• 创建一个聚合组，它们共享同样的速率和双工设定。根据 802.3ad 规范将多个 slave 工作在同一个激活的聚合体下。<br>• 必要条件：①ethtool 支持获取每个 slave 的速率和双工设定；②switch(交换机)支持 IEEE 802.3ad Dynamic link aggregation；③大多数 switch(交换机)需要经过特定配置才能支持 802.3ad 模式 |
| balance-tlb | 适配器传输负载均衡 | • 根据每个 slave 的负载情况选择 slave 进行发送，接收时使用当前轮到的 slave。该模式要求 slave 接口的网络设备驱动有某种 ethtool 支持；而且 ARP 监控不可用。<br>• 不需要任何特别的 switch(交换机)支持的通道 bonding。在每个 slave 上根据当前的负载（根据速度计算）分配外出流量。如果正在接受数据的 slave 出故障了，另一个 slave 接管失败的 slave 的 MAC 地址。<br>• 必要条件：ethtool 支持获取每个 slave 的速率 |
| balance-alb | 适配器适应性负载均衡 | • tlb 基础上增加了 rlb(接收负载均衡 receive load balance)。不需要任何 switch(交换机)的支持。接收负载均衡是通过 ARP 协商实现的。<br>• 该模式包含了 balance-tlb 模式，同时加上针对 IPV4 流量的接收负载均衡(receive load balance, rlb)，而且不需要任何 switch(交换机)的支持。接收负载均衡是通过 ARP 协商实现的。bonding 驱动截获本机发送的 ARP 应答，并把源硬件地址改写为 bond 中某个 slave 的唯一硬件地址，从而使得不同的对端使用不同的硬件地址进行通信。 |

SE8-288 配置 enp4s0f0(GE1) 和 enp4s0f1(GE2) bonding 模式为 balance-rr 的方式如下：登录控制板，修改网络配置文件，示例如下：

```
se6@se6-desktop:~# sudo vim /etc/netplan/02-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    enp4s0f0:
      dhcp4: no
    enp4s0f1:
      dhcp4: no
  bonds:
    bond0:
      interfaces: [enp4s0f0, enp4s0f1]
      addresses: [192.168.1.131/24]
      gateway4: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8]
      parameters:
        mode: balance-rr
```

应用生效：
`sudo netplan apply`

删除 bond 模式：
`sudo ifconfig bond0 down`
`sudo rmmod bonding`

修改 bond 模式方式：
修改 `parameters: mode: balance-rr` 配置模式；`ifconfig bond0 down` 卸载虚拟网卡，然后使用 `rmmod bonding` 卸载模块；最后就可以通过 `netplan apply` 使修改应用生效。

**注意**

- 配置聚合模式后，需要修改 `/root/se6_ctrl/iptable_setup.sh` 的 `wanname=$(ifconfig | grep enp | awk -F : 'NR==1{print $1}')` 为 bond 网口的名。

#### 5.6.2 IP 修改

**说明**

- 步骤 2-1 使用 `$ bm_set_ip $` 命令修改 IP 为固定 IP，enp4s0f0 为 GE1 口网卡名称。

- 步骤 2-2 使用 `bm_set_ip_auto` 命令修改 IP 为 DHCP。

- 结束

**说明**

- 修改控制板 GE1 口（enp4s0f0）IP，不会自动做端口映射，需用户手动执行 `/root/se6_ctrl/iptable_setup.sh` 进行端口映射。
- 算力核心板的 IP 是由控制板在开机过程中设置的，如果单独修改了控制板 GE1 或 GE2 的 IP，必须执行 `reboot_all` 命令重启整机，否则会导致核心板无法连通、端口映射异常。

- SE8-288 算力核心板上内存采用 LPDDR4x，每个算力核心板使用 4 颗 4GB DDR 颗粒，总容量为 16GB。默认情况下，内存空间分配情况为，系统内存：6.9GB，TPU：2.5G，VPU：3GB，VPP：3GB。用户可参照 SoC 模式下内存空间分配的修改方式和工具来自定义修改。

### 7.3 控制板给算力核心板执行脚本

控制板/root/se6_ctrl/script 目录下提供了 core_run_command_bynet.sh 脚本方便客户快速获取算力核心板信息以及执行命令。

使用帮助：

```
./core_run_command_bynet.sh "shell command" username passwd [id]
./core_run_command_bynet.sh "/bm_bin/bm_version" linaro linaro
./core_run_command_bynet.sh "/bm_bin/bm_version" linaro linaro 4
```

**说明**

- 如果没指定 id，会对所有算力板执行"shell command"命令
- shell command 支持连续命令，使用"'"包括即可。

例如，如果想实现拷贝功能可以使用如下命令：

```
./core_run_command_bynet.sh "~/script/scp_file2dir_local.exp 192.168.1.107 linaro linaro ~/test ~/" linaro linaro
```

其中：

- 192.168.1.107 为控制板 GE1 口 IP
- 引号里的 linaro linaro 为控制板的用户名和密码
- ~/test 为控制板上的文件源路径
- ~/ 为拷贝到算力核心板上的目的路径
