# 批量部署工具（批量执行工具）

面向多台设备的批量运维工具：在多台 SSH 可达的设备上批量执行命令、批量上传/下发文件、
批量下载文件，并逐台汇总执行结果。

**当前实现：Go + Fyne（桌面） / Go 标准库（Web），Linux / Windows 均为单个可执行文件。**
历史版本为 Qt 5 实现（AppImage + Enigma Virtual Box 打箱），已由本实现取代。

两种 Linux 产物，按目标机器是否有图形栈选择：

| 产物 | 形态 | 适用场景 |
| --- | --- | --- |
| `..._linux_amd64` | 桌面版，动态链接 X11/GL | 有桌面环境的机器：Fyne GUI + `--web` 都可用 |
| `..._linux_amd64_headless` | **静态链接，零图形依赖**，8MB | **无图形栈的服务器**：无参数即启动 Web UI |

> 为什么必须分两种：Fyne 的 Linux 产物动态链接 `libX11`/`libGL`/`libwayland`，
> 在没有图形栈的服务器上**加载器直接报缺 so**，不是"看不到窗口"而是起不来。
> headless 版用 `-tags headless` 完全不编译 Fyne 代码，`CGO_ENABLED=0` 静态链接，
> 所以能在纯命令行服务器上直接跑。

## 1. 运行

```
qt_batch_deployment                            启动界面（桌面版=GUI，headless 版=Web UI）
qt_batch_deployment --web [--listen 地址:端口]  启动 Web UI（两种构建都可用）
qt_batch_deployment [根目录] [配置文件路径] [最大并行数]   命令行批处理
```

| 参数 | 说明 |
| --- | --- |
| 根目录 | 文件类操作的基准目录，需为绝对路径 |
| 配置文件路径 | JSON 配置文件路径，需为绝对路径 |
| 最大并行数 | 并发执行的设备数上限，默认 100 |

退出码：`0` 全部成功；`1` 有设备执行失败；`2` 参数或配置错误。
（旧版在参数错误时返回 0，脚本调用方无法判断失败，此处已修正。）

### 1.1 Web 模式（无图形栈服务器）

```bash
./qt_batch_deployment_..._linux_amd64_headless --web --listen 127.0.0.1:8080
```

**默认只监听 127.0.0.1**，因为配置文件里是**明文 SSH 密码**。要在别的机器上访问，
推荐 SSH 端口转发：

```bash
ssh -L 8080:127.0.0.1:8080 linaro@<服务器>
# 本地浏览器打开 http://127.0.0.1:8080
```

确需直接对外时显式 `--listen 0.0.0.0:8080`，并自行在前面加认证（反代/防火墙）。

Web 界面与桌面版功能对齐：设备/操作增删改克隆、三段式操作配置、完整度实时提示、
根目录与并行上限、内置预设、配置导入导出、执行、逐设备实时状态与日志、中止。

## 2. 图形界面

桌面版（Fyne）与 Web UI 使用**同一套布局与视觉规范**（`src/theme.go` 与
`src/webui/index.html` 的 `:root` 变量一一对应），自上而下：

- **顶栏**：SOPHGO Logo、标题、版本号、执行中标记；右侧官网链接与帮助。
- **控制卡片**：文件操作根目录；内置预设 + 载入 / 保存（Web 为导入 / 导出）；
  并行上限；「中止」与主按钮「执行配置」。
- **左卡片 远程设备**：工具栏（新增 / 克隆 / 编辑 / 删除）→ 概览统计
  （总数 / 成功 / 失败 / 进行中）与成功-失败比例条 → 设备表 → 选中设备的执行日志
  （深色终端区，失败行红色、成功行绿色，可一键复制）。
- **右卡片 操作序列**：工具栏（新增 / 克隆 / 删除）→ 操作表（类型彩色标签）→
  编辑区：操作名称、操作类型分段选择（命令下发 / 文件上传 / 文件下载）、对应表单、
  完整度徽标。

视觉规范：

- 主色取自 SOPHGO logo 蓝；红色只用于「删除 / 中止」等破坏性操作，主次分明。
- 灰底 + 白色圆角卡片分区；状态一律「色块 + 文字」双编码（成功绿 / 失败红 /
  等待橙 / 执行中蓝），不只靠颜色。
- 固定浅色主题 + 内嵌思源黑体，中文在各平台字形一致；对话框按钮为中文。

相对旧版的交互改进：

- **编辑即时生效**，不再需要先按「储存该项」——旧版忘了按就会丢配置。
- **操作类型只有一个入口**（分段选择器），不再「下拉框 + 标签页」两处同步。
- **不完整的操作明确标注**并自动跳过（命令行模式会逐条列出跳过原因）。
- **执行期间配置区整体禁用**，并新增「中止」按钮可随时中断；结束后自动恢复。
  取消会直接关闭底层 SSH 连接，阻塞中的命令与传输立即返回，不用等超时。
- 「新增设备」后直接弹出编辑框；Web 版双击设备行即可编辑，编辑 / 确认 / 帮助
  均为页内弹窗（不再使用浏览器原生 prompt / confirm / alert）。
- 旧版会闪退的操作（删到空表、未选中即点保存、读入空配置）现在都给出明确提示。

## 3. 配置文件格式

与旧版完全兼容，旧配置文件可直接使用，无需迁移：

```json
{
    "remoteInf": [
        {"IP": "172.16.140.11", "Port": 22, "Username": "linaro", "Password": "linaro"}
    ],
    "operationInf": [
        {"name": "检查时间", "type": 0, "commandStr": "date",
         "checkSuccessStr": "", "checkErrorStr": "",
         "transferFileSourcePath": "", "transferFileDestinationPath": "", "checkFile": 0}
    ]
}
```

`type`：`0`=下发命令，`1`=上传文件，`2`=下载文件。
`checkFile`：`0`=MD5 校验，`1`=文件大小校验，`2`=不校验。

两个**可选**顶层字段用于调整超时（旧配置没有它们，行为不变）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `commandTimeoutSec` | 300（5 分钟） | 单条命令的超时秒数。刷机、升级等长任务需要放宽时配置 |
| `transferTimeoutSec` | 1800（30 分钟） | 单次文件传输的超时秒数。大镜像 + 慢链路时放宽 |

```json
{
    "commandTimeoutSec": 1800,
    "transferTimeoutSec": 7200,
    "remoteInf": [...],
    "operationInf": [...]
}
```

超时是「硬上限」：到点会关闭底层连接并判该设备失败，不会无限等待。

字段名刻意保持旧版的大写形式（`IP`/`Port`/`Username`/`Password`），
以保证双向兼容。

## 4. 三项操作的语义

| 操作 | 行为 | 校验 |
| --- | --- | --- |
| 命令下发 | 在每台设备执行同一条命令 | 可选「成功关键字 / 失败关键字」，都为空则不校验 |
| 文件上传 | 本地文件 → 设备指定路径（目标以 `/` 结尾时拼上原文件名） | 按配置的 `checkFile`（默认 MD5） |
| 文件下载 | 设备文件 → 本地目录（文件名带 `IP_端口_时间戳_原名`） | 按配置的 `checkFile`（默认 MD5） |

`checkFile` 三档在界面上是「校验方式」下拉，在配置里是数字，两者一一对应：
`0`=MD5、`1`=文件大小、`2`=不校验。旧版界面把这项写死成 MD5 且不回显配置值，
载入 `checkFile: 2` 的配置后界面上仍显示 MD5 —— 本版按下拉真实回显与回写。

> **行为变更（重要）**：旧版「失败关键字」实际上从未生效——代码在错误分支里判断的
> 是成功关键字。本版按配置语义正确实现：命中失败关键字即判定失败，未命中成功关键字
> 也判定失败。若历史配置依赖了旧版的失效行为，升级后可能开始报失败，这是预期修正。

## 5. 相对旧版修掉的问题

崩溃（旧版可稳定复现 SIGSEGV）：

- 设备表格删到空行后，选中变更回调解引用空指针。
- 未选中任何操作就点「储存该项」。
- 读入 `remoteInf` 为空的配置后强制触发 `itemChanged(nullptr)`。
- 连接失败等错误路径上的资源清理缺陷。

功能与健壮性：

- 「失败关键字」从未生效（见 §4）。
- 远端输出为空时 `split(" ").at(0)` 越界。
- `sftp_write` 返回值未判负会导致死循环。
- 下载不检查本地写入结果，磁盘满时会「成功但内容残缺」。
- 无连接超时、无 keepalive，挂死设备会永久占坑。**现为**：连接/握手/命令/传输
  四段各自限时，另有 30 秒 keepalive 探测；超时设在底层连接上，因此服务端
  「收下请求但永不回应」也能被打断（有专门用例覆盖）。
- 远端 `fsync` 无上限重试，服务器不支持时永久卡死。
- 缺少 `remoteInf`/`operationInf` 时静默继续，现已显式报错。
- 不再使用 `echo <密码> | sudo -S`，密码不会出现在进程命令行里。
- GUI 与命令行对「不完整操作」的处理口径不一致，现统一为「跳过并说明原因」。

## 8. 局域网扫描

设备区工具栏的「扫描局域网」可以按 MAC 前缀批量发现设备并一次性加入设备列表。

### 8.1 为什么用 ARP

| 方式 | 会不会触发防火墙 | 能否拿到 MAC |
| --- | --- | --- |
| **ARP（本功能采用）** | **不会经过网关，也不依赖目标机开放端口** | 能 |
| ICMP ping | 目标机防火墙常拦 ICMP | 不能 |
| TCP 端口探测 | 会命中防火墙规则，日志里就是"扫描" | 不能，且只能发现开了端口的设备 |

ARP 是二层广播：请求由本机网卡直接发出，只在本网段内传播，**不经过网关**，
目标机的 iptables/firewalld/Windows 防火墙也看不到它。这也是唯一能拿到 MAC 的方式，
而"按 MAC 前缀筛选"是本功能的硬需求。

### 8.2 权限

发送 ARP 需要 `CAP_NET_RAW`：

```bash
# 方式一：用 root 运行（推荐，最简单）
sudo ./qt_batch_deployment_..._linux_amd64_headless --web

# 方式二：给二进制单独授权（不需要每次 sudo）
sudo setcap cap_net_raw+ep ./qt_batch_deployment_..._linux_amd64
```

> 注意：若程序放在 `/tmp` 等带 `nosuid` 挂载的目录，setcap 设置的能力会被忽略，
> 这时只能用 root 运行。

**没有权限时不会报错中断**，而是降级为读取本机 ARP 缓存（`/proc/net/arp`）：
只能看到最近通信过的设备，界面上会明确提示原因和授权方法。

### 8.3 参数

| 参数 | 说明 |
| --- | --- |
| 网口 | 从本机网卡中选择，默认选中**有默认路由**的那块 |
| 网段 | CIDR 格式，如 `192.168.1.0/24`；也接受单个 IP。上限 /16 |
| MAC 前缀 | 长度任意，`98`、`f8:ed`、`98a92d`、`00-1A-2B` 都可以；留空表示不过滤 |
| 等待时间 | 收 ARP 应答的时长，默认 4 秒 |

扫描结果默认全选，填好统一的 SSH 端口/用户名/密码后点「添加选中设备」即可批量加入。
已存在的 IP 会自动跳过。

### 8.4 关于防火墙的说明（重要）

本功能默认**不会**产生跨网段流量，因此通常不触发网关防火墙。但以下情况仍可能告警：

- 网段填成了跨网段地址（例如从 `192.168.1.0/24` 的机器去扫 `10.0.0.0/24`）；
- 本机或接入交换机上启用了网络监控 / IDS / 端口安全（ARP 广播数量突增会被记录）；
- 交换机配置了 DHCP snooping 或动态 ARP 检测（DAI），大量 ARP 可能被丢弃或告警。

程序界面在扫描页固定标注了这条提示。请在获得网络管理授权后再使用。

### 8.5 平台支持

| 平台 | 主动 ARP 扫描 | 说明 |
| --- | --- | --- |
| Linux | 支持 | 需要 CAP_NET_RAW；无权限时降级读 ARP 缓存 |
| Windows | **不支持** | 发原始以太帧需要 Npcap 等额外驱动，与单二进制交付冲突；界面会明确报错 |
