# SE写卡工具 (Windows) — sewriter v2.0.4

给现场/产线用的 **SE 系列设备 TF 卡制作程序**：选卡 → 二次确认 → 写入 → 写后回读校验。
既能烧录整盘镜像，也能把一批文件直接做成 **MBR+FAT32 刷机卡**（SE5/SE7/SE9）。

**默认构建不带内置镜像**：程序起来后在界面里选数据源（发版文件包 `.zip` / 目录 / 整卡镜像），
或者用「浏览文件…」直接指到卡内容包上。想做成"插卡即烧、不用带镜像文件"的版本，
用 `--image <文件包>` 编一个自带镜像的 exe，**或者直接让程序自己生成** ——
界面点一个按钮（`repack`）就能产出另一个自带新镜像的程序，不需要构建机、不需要 Go 环境。

- 平台：**Windows 7 及以上**（32 位 / 64 位都出；单文件 exe，无需安装任何运行时）
  - **默认交付 `sewriter.exe` 是 32 位版本** —— Windows 7 32 位与 64 位都能直接跑
  - 另有 `sewriter-x64.exe`（64 位，体积略小、速度略快）
  - **启动自动索要管理员权限**（manifest 里 `requireAdministrator`，双击即弹 UAC）——
    读写物理盘必须管理员，普通权限下设备列表会是空的
- 源码：`source/sewriter/`（Go，GUI 用 lxn/walk，磁盘操作用 Win32 API）
- 产物：`output/sewriter/`（`bash source/sewriter/release.sh` 交叉编译产出；本地中间物在其 `output/`）
- 工具版本：`source/sewriter/VERSION`（当前 2.0.4）

## Windows manifest（**改 GUI 相关代码前务必先读**）

exe 必须嵌入应用程序 manifest（`sewriter.manifest` → `sewriter.rc` → `rsrc_windows_<arch>.syso`），
否则 Windows 只加载 **comctl32 v5**，而 lxn/walk 是 Unicode 程序、tooltip 用 `TTM_ADDTOOLW`
（`WM_USER+50`，v5 不支持）→ **启动即报 `TTM_ADDTOOL failed` 并退出**。

manifest 声明了：`Microsoft.Windows.Common-Controls 6.0.0.0` + `PerMonitorV2` DPI +
**`requireAdministrator`**（启动自动索要管理员权限）。`processorArchitecture` 用 `*`，
一份 manifest 同时服务 32/64 位两个构建。

`build.sh` 每次构建都会用 `windres` 重新生成两个 `.syso`
（amd64 用 `x86_64-w64-mingw32-windres`，386 用 `i686-w64-mingw32-windres`；无 windres 时沿用仓库里的那份）。

**改完必须验**：`python3 check_exe.py <exe>...` 会从 PE 结构里直接检查
位宽 / PE 子系统版本 ≤ 6.01（Win7）/ `RT_MANIFEST(24)` 是否存在且含 `requireAdministrator`。

> 命令行走的是另一条路径（不初始化 walk），manifest 缺失时 CLI 仍可用 —— 启动失败弹窗里也会提示这一点。

## 支持哪些镜像 / 压缩包（v1.3.0 起）

| 来源 | 形态 | 写入方式 |
|---|---|---|
| 裸磁盘镜像 | `.img` `.raw` `.iso` `.dd` `.wic` | 整盘写入 |
| 压缩的整盘镜像 | 上述镜像经 `gz / xz / bz2 / zst` 压缩 | 解压后整盘写入 |
| 归档内的单个镜像 | 容器为 `zip / 7z / rar / tar / tar.gz / tar.xz / tar.bz2` | 取出该镜像整盘写入 |
| **文件包** | 容器内是一批文件（`boot.scr`、`fip.bin`、`*.itb`、`recovery-ui/` …） | **快速格式化**目标卡为 MBR+FAT32，再写入文件 |

### 文件包：自动定位刷机包根目录（v1.9.0 起）

现场拿到的压缩包常常**多套了一层目录**：

```
sdbootrecoveryfiles/boot.scr
sdbootrecoveryfiles/fip.bin
sdbootrecoveryfiles/sdbootrecovery.itb
sdbootrecoveryfiles/recovery-ui/…
```

按原样写进卡，卡根目录下只有 `sdbootrecoveryfiles/` 这一层，设备的 BootROM/BL2/u-boot
在卡根目录找不到 `boot.scr` / `fip.bin` —— 卡做出来了却起不来。

程序会按**特征文件**（`fip.bin` 权重最高，其次 `boot.scr`、`*.itb`，另看 `recovery-ui/` 目录）
判断哪一层才是刷机包根目录，**把那层前缀剥掉**，让这些文件真正落到 TF 卡根目录：

```
fip.bin            ← 卡根目录
boot.scr
sdbootrecovery.itb
recovery-ui/
说明.txt            ← 包外文件保持原路径，不丢
```

判定规则（都写进了单测）：

| 情况 | 行为 |
|---|---|
| 特征文件本来就在根目录 | **一个字节都不动** |
| 唯一一个目录含特征文件 | 剥掉该层前缀，包内文件落到卡根目录 |
| 多个目录都像刷机包（如 `se5/` 与 `se7/`） | **不猜**，保持原样并在界面/日志明确警告 |
| 没有任何特征文件 | 不动 —— 不靠"只有一层目录"这种猜测（剥错一层同样起不来，且更难排查） |
| 剥前缀后出现重名 | **直接报错**，不静默互相覆盖 |
| 包外文件 | 保持原路径写入，并如实报出数量 |

界面 ② 面板与命令行都会列出 `刷机包目录：已把 xxx/ 这一层去掉 —— 卡根目录下就是刷机包内容`。

### 文件包模式：直接在卡上建 FAT32（不生成中间镜像）

归档**流式解压出来的字节直接落到卡上**，中间不产生任何整卡尺寸的临时文件 —— 一张 14 GiB 的卡
不会先落一个 14 GiB 的镜像再整份读回来写。由此：

- **天然就是快速格式化**：只写文件系统元数据 + 真实文件数据，未使用空间一个字节都不碰。
  实测 200 MiB 卡只写 **7.4 MiB**；14 GiB 的卡写入量同样是"内容大小"量级。
- **少一遍整卡读 + 一遍整卡写**，也不占临时盘、不占系统文件缓存。
- 卡头 1 MiB（分区表之前）会先清零，避免用过的卡残留上一任的引导代码/分区痕迹。

### 两级校验（写完自动做，失败则退出码非 0）

1. **回读校验**：回读卡上的分区表 / 引导扇区 / **FAT 两份副本逐字节比对**（副本不一致必被发现），
   并核对 MBR 与 BPB 自洽（分区扇区数 == BPB 总扇区数）
2. **文件级校验**：**从卡上**挂载 FAT32，逐个文件读回算 sha256 与源压缩包比对

> 卡是直接在设备上建的，没有"中间镜像"可逐字节比对 —— 所以回读校验核对的是**结构化事实**
> （分区表 / BPB / FAT 两份副本），文件内容的逐字节保证由文件级 sha256 校验负责。

- **强制落盘**：写句柄带 `FILE_FLAG_WRITE_THROUGH`，写完 `FlushFileBuffers` 后**关闭写句柄、重新只读打开**再校验，
  避免系统写缓存造成"假通过"。

### 整盘镜像模式的稀疏写入

SE7 恢复镜像九成以上是全零。写整盘镜像时，**源块全零且卡上该处读回来也全是零 → 整块跳过不写**
（判零粒度 = 写入分块 1 MiB）。卡上那块有旧数据时照样会写下去，结果与逐字节写完全一致。

实测 512 MiB 镜像（内容 10 MiB）→ 实写 **10 MiB**、跳过 502 MiB，回读 sha256 一致。
读比写快得多，所以在"卡本来就是零"的常见场景下总耗时明显下降。

### 大压缩包：分析不卡界面

`.tar.xz` 文件包要枚举条目就得把整条压缩流走一遍（几十秒到几分钟）。分析一律在**后台线程**做：

- 进度条显示已消费的压缩字节数百分比（容器格式没有字节进度 → 跑马灯）
- 状态行前的动态图标持续转，一眼看出程序还在干活
- 「取消分析」按钮可随时中止
- 连点不同文件时，先发起的分析结果会被丢弃，不会覆盖新结果

判定按**内容**（魔数）而非扩展名；归档里只有一个"像磁盘镜像"的文件时按整盘写作，否则按文件包处理。

```bash
# 整盘镜像（自动识别压缩格式）
sewriter.exe write --disk 3 --image disk.img.tar.xz --yes

# 文件包 → 格式化为 MBR+FAT32 刷机卡（默认整卡容量）
sewriter.exe write --disk 3 --image se7-flashcard.zip --yes

# 只按内容大小建分区（更快；卡上剩余空间不参与该分区）
sewriter.exe write --disk 3 --image se7-flashcard.zip --fs-size auto --yes

# 强制指定写入方式 / 卷标
sewriter.exe write --disk 3 --image x.bin --as raw --yes
sewriter.exe write --disk 3 --image pkg.zip --as files --label SE7BOOT --yes
```

### 中文文件名（v1.5.0 起支持）

FAT32 的长文件名（LFN）以 UCS-2 存名字，**中文/日文/韩文本来就合法**。此前写不进去是依赖库
go-diskfs 写入路径的 bug，已在 `third_party/go-diskfs` 打了 4 处补丁（见该目录 `PATCHES.md`）：

1. 短名生成把 rune 截断成字节判合法性 → 汉字被误当合法字符，算 LFN 校验和时失败
2. 名字被改写后没做 `~N` 去重 → 同目录可能出现重复的 8.3 短名
3. LFN 槽数按**字节数**而非字符数计算 → 多写的槽用 `0xFFFF` 填充
4. 读取端不认 `0xFFFF` 填充 → 还原出的名字尾部带乱码，按名字查不到文件

另外：中文 Windows 上打的 zip 常用 **GBK** 存文件名，已加兜底解码（否则卡上是乱码名）。

仍然不支持（FAT32 本身存不下，会前置拦下并说明）：
- BMP 之外的字符（emoji 等）
- FAT 非法字符 `< > : " / \ | ? *` 与控制字符

## 界面布局约定（改 UI 前先读）

窗口按 Rufus 的**紧凑单列**范式组织，改布局时请沿用，否则很容易又变回"控件乱、占屏大、没顺序"：

| 约定 | 原因 |
|---|---|
| 窗口固定紧凑（660×640），**不要用表格堆信息** | 上一版 1000×880 在 200% 缩放屏上渲染成 1956×1742，占掉大半个屏幕 |
| 分组标题**只写"这一步做什么"**，编号 ①②③ 表明顺序 | 标题里塞解释（"目标设备 — 选择要烧录的 TF 卡"）会让重点糊掉 |
| **说明文字一律进 `ToolTipText`**，控件上只留短标签 | 悬停才需要的解释不该常驻界面（"含需人工确认的固定盘"…） |
| 设备/镜像用**下拉框 + 紧凑属性表**，不用多列表格 | 空表格会占掉一大块版面 |
| 状态行实时显示"下一步该做什么"（`updateHint()`） | 顺序指引；未选设备时「开始写入」置灰 |
| **耗时操作（分析归档）放后台线程 + 进度条 + 动态图标 + 可取消** | 放 UI 线程就是"选完文件界面直接卡死"（大 .txz 要解几分钟） |
| **写卡动线之外的动作放菜单**（如"导出内置镜像程序"） | 维护动作不该夹在日常写卡流程中间 |
| 有**真实数据**的只读信息用两列「项目/内容」表格（`kvModel`） | 表格能自动对齐，适合设备属性/分区这类多字段数据 |
| 只是**说明性文字**（如"未选择镜像该怎么操作"）用普通文本行，不要套表格 | 说明排成"项目\|内容"两列反而莫名其妙；文本按"标签：值"逐行写，不做列对齐（比例字体下对齐必错） |
| 需要文本对齐时用 `padRight()`（按 `displayWidth` 计，中文算 2 列） | 命令行输出用；GUI 里优先用真表格 |
| 按钮给 `MaxSize` 固定宽度 | 避免不同 DPI / 窗口宽度下按钮忽宽忽窄 |
| 日志用 `logDedup` 抑制连续重复 | 反复刷新磁盘不再刷屏 |

## 快速使用

1. 把 `sewriter.exe` 拷到 Windows 机器双击运行 —— **程序自己会弹 UAC 索要管理员权限**
   （manifest 里 `requireAdministrator`）。点「是」即可；若域策略禁止提权，程序仍能启动，
   但读写物理盘会失败（设备列表为空，状态行提示"第 1 步：请选择目标设备"）。
2. 插入 TF 卡（读卡器）。
3. **① 选择目标设备**：点「刷新」→ 在下拉框里选目标卡（系统盘不会出现；固定盘需勾「全部」）。
   下方会显示设备属性与现有分区。
4. **② 选择镜像**：默认用程序自带的内置镜像（信息表里显示文件名/大小/sha256）；
   要烧别的才点「浏览…」选外部文件，点「内置镜像」可切回。
5. **③ 开始写入**：核对目标设备 → 勾选确认框 → 点「开始写入」→ 二次确认「是」
   → 等待写入 + 两级校验 → 通过后拔卡即用。

> 界面按 ①②③ 三步排列，状态行始终告诉你"下一步做什么"。所有解释性文字都在鼠标悬停提示里。

## 换掉默认镜像 → 生成第二个程序（程序自己做，无需构建机）

菜单 **「工具 → 导出自带镜像的新程序…」**（不在写卡动线上，避免干扰日常操作）：

1. 选一个 `.img` / `.img.gz`；
2. 选新程序的保存位置（默认与当前程序同目录、按镜像版本命名，如 `sewriter-1.5.2.exe`）；
3. 确认 → 生成 → 程序自动回读自检（骨架一致 + 内置数据 sha256 一致）→ 提示新程序路径与 sha256。

命令行等价操作：

```
sewriter.exe repack --image <新的 .img/.img.gz> [--out <新程序路径>] [--force]
sewriter.exe repack --image X.img.gz --skeleton <模板 exe> --out <新程序>   # 指定骨架
```

**原理**：程序文件结构是 `[程序骨架][镜像数据][元信息]`。

- 读内置镜像 = 从自己尾部按偏移流式读取（不占内存，2 GiB 镜像也能直接烧）
- 换镜像 = 剥离自己的镜像段得到**纯净骨架** → 追加新镜像 → 写成另一个文件
- 因此**新程序同样能继续换镜像**，可链式进行；旧镜像会被剥离，体积不会叠加
- **本程序自身不会被修改**（运行中的程序也不会被覆盖）

生成新程序时的其它行为：

| 情况 | 行为 |
|---|---|
| 输入 `.img.gz` | 直接存压缩体（程序体积小）；解压 sha256 优先读发版包 sidecar `.info`，无则现场流式解压计算 |
| 输入 `.img` | 原样存入（程序体积 = 骨架 + 镜像大小） |
| 输出文件已存在 | CLI 需 `--force`；界面会弹覆盖确认 |
| 输出路径 = 程序自身 | 拒绝（防止自毁） |
| 生成过程出错 | 自动删除半成品，不会留下坏程序 |

## 命令行（自动化 / 排查）

```
sewriter.exe info                             内置镜像版本信息 + 本机磁盘
sewriter.exe list [--all]                     列出磁盘（--all 含"需人工确认"的固定盘）
sewriter.exe repack --image <img[.gz]> [--out <新程序>] [--force]
                                              换镜像生成第二个自带镜像的程序
sewriter.exe hash [--image <img[.gz]>]        计算镜像内容 sha256（省略 --image = 内置镜像）
sewriter.exe write --disk 3 [--image <img[.gz]>] [--yes] [--no-verify] [--force]
sewriter.exe verify --disk 3 [--image <img[.gz]>] [--bytes N] [--fs-size full|auto|<MiB>]
                                              只读校验，不写盘 (文件包模式校验卡上 FAT32 结构与文件)
```

不指定 `--image` 时一律使用**内置镜像**（默认行为）。

- `--disk` 可写磁盘号（`3`）或设备路径（`\\.\PhysicalDrive3`）
- `--force` 才允许写"需人工确认"的固定盘；系统盘永远拒绝
- 无参数运行 = 图形界面；退出码 0=成功 / 1=失败 / 2=用法错误

## 安全设计（防误写本地盘）

| 机制 | 说明 |
|---|---|
| **系统盘永不可选** | 含 Windows 系统卷的物理盘恒不出现在列表中（`list --all` 也不显示），从根上杜绝"把系统盘烧了" |
| **自动避开本地固定盘** | 按总线类型分级：`USB / SD / MMC / 可移动介质` → 「可安全烧录」默认可见；`SATA / NVMe / RAID` 等固定盘 → 「需人工确认」默认隐藏，需勾选「显示全部磁盘」+ 二次确认才可选 |
| **分区核对** | 选中后展示磁盘型号/容量/总线/全部现有分区（含盘符、卷标、大小），确认框要求操作者逐项核对后手动勾选 |
| **二次确认** | 勾选确认框后仍弹 Yes/No 对话框（默认按钮为「否」），并列出目标盘与镜像摘要 |
| **容量预检** | 目标小于镜像直接拒绝（大镜像靠发版包随附的 `<镜像>.info` 取解压大小，见下） |
| **先强制卸载再锁定卷** | 写盘前对目标盘上的**所有**卷（含没有盘符的分区，用 `FindFirstVolume` 枚举）先 `FSCTL_DISMOUNT_VOLUME` 强制卸载，再 `FSCTL_LOCK_VOLUME` 锁定（带 20 次重试）。直接锁定会以 `Access is denied` 失败 —— 卷还被文件系统挂着时不接受锁定，但接受卸载 |
| **写后回读校验** | 写完全量回读，与镜像逐块比对；报告首个不一致偏移与不一致字节数（`--no-verify` 可关，不建议） |
| **repack 不改自身** | 生成新程序只写新文件；输出路径等于程序自身直接拒绝 |

> ⚠ 仍需人工确认：本工具做的是"尽力而为"的自动判定，最终以操作者核对为准。

## 镜像 sidecar（`<镜像>.info`）

发版包里的 `.img.gz` 旁边会有同名 `.info`：

```
file=se7-recovery-1.5.0-2026-09-14.img.gz
bytes=8589934592
sha256=d83d7205f8cb...
```

作用：GNU gzip 对 ≥4 GiB 输入会把尾部 ISIZE 回绕为 0，工具无法从 gz 头得知解压大小 →
读 sidecar 才能做**容量预检**和百分比进度。sidecar 缺失时仍可烧录（进度显示"已处理量"），
但**没有容量预检**，请自行确认卡容量 ≥ 镜像大小。repack 打包时 sidecar 还用于免去解压重算 sha256。

## 构建（Linux / 交叉编译，无需 Windows 环境）

sophon-tools 统一接口（构建机/CI 走这个）：

```bash
bash source/sewriter/release.sh                      # 默认: Windows 32+64 位, 不带内置镜像
bash source/sewriter/release.sh windows 2.0.4        # 显式指定平台与版本
bash source/sewriter/release.sh all                  # 再附带 Linux CLI (本机自测用)
```

直接调底层构建脚本（开发时更顺手，参数更细）：

```bash
bash source/sewriter/build.sh                # 默认: Windows 32+64 位, 不带内置镜像
bash source/sewriter/build.sh --image <文件包> # 额外产出 sewriter-embedded.exe
bash source/sewriter/build.sh --linux        # 附带 Linux CLI (repack / 本机自测)
bash source/sewriter/build.sh --test         # 附跑单测
```

> 默认形态（MYSWY 2026-09-15）：**只出 Windows、不带内置镜像**。其余平台按需再加。

**Windows 7 支持**：Go 1.21 起官方最低要求是 Windows 10（PE 子系统版本写成 10.0，Win7 加载器
直接拒绝）。所以 Windows 产物用 **Go 1.20** 编译（`WIN7_GO`，默认 `go1.20.14`，首次会自动下载），
依赖也全部锁到 Go 1.20 可编译的版本（见 `go.mod` 与 `third_party/go-diskfs/PATCHES.md` 补丁 6）。
构建完 `build.sh` 会自动跑 `check_exe.py` 验证"32 位 / Win7 / 管理员"三条底线，
不满足就直接失败 —— 不会悄悄产出一个跑不起来的 exe。

打包流程与程序内换镜像是**同一段代码**：编译出骨架 → 调用 `sewriter-linux repack` 追加镜像。
仓库不保存大镜像文件，clone 后带上 `--image` 跑一条命令即可产出内置版。
