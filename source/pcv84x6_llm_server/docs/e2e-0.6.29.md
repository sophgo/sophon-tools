- **环境**：用户提供的 10155 新环境（CV84X6，NPU 30 GiB + VPP 4 GiB，系统内存 28 GB，内核 5.10.4，libsophon 0.4.15），2026-11-07 至 2026-11-08。
- **被测版本**：
  - RC1：main `85cfa22`，原生库在板上编译，deb sha256 `7d8c05e0…08ff64b`；
  - RC2：main `a3f3fc9`（含修复 #115–#117），原生库在板上编译（md5 `aedc9061…`），deb sha256 `4674be43…df1f2d55`；
  - 最终包：main `2605ade`（RC2 + #118），deb sha256 `4e1e564f…7ebbc5`。
- **执行**：技术负责人主导（用户要求）。D5 / D6 / D7 的修复与复现由 CV84X6-BSP开发agent 完成（MYS-2691）。
- **方法**：测试脚本在 `tools/e2e/`，从 13.24 经 SSH 隧道访问板子；每个检查写一行证据到证据库（`tools/e2e/ledger/`）。下面的表格由 `tools/e2e/report_tables.py` 从证据库生成。同一项被重新判定时，以最后一次为准，首判与原因列在「复判记录」中。

## 结论

**v0.6.29 可以发布。** 发现 9 个问题（D1–D3、D5–D9、U1/U2）加 2 处文档问题，除 D7 外全部修复并在板上复测通过；D7 不是本版本引入，作为已知问题发布，另开子任务继续追。

- RC1（修复前）：191 项检查，187 通过、4 失败。4 项失败对应 D2/D3（`kb_read`）、D6（两项接管）、D7（TPU 卡死）。
- RC2（含修复 #115–#117）：159 项检查全部通过。复测了所有修复点，并回归了 A2–A5、A7–A9。
- 最终包（RC2 + #118）：重新安装，冒烟通过（4 个模型加载，embeddings / rerank / OCR VL 模式 / OpenAI 错误格式），控制台 20 个页面检查通过。
- 性能问题 P1（混合负载下 Embedding 拖慢对话）未改，需要用户决定是否改用 seq512 的 Embedding 模型。

RC2 没有完整重跑 A1、A6、A10：A1 用最终包重新安装做了验证；A6 只复测了与修复相关的 agent 接管；A10 用 D7 的两组 9 分钟满负载实验代替。
