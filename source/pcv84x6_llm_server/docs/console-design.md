# 控制台视觉规范（Refactoring UI）

> 面向 `web/` 的前端实现约定。架构与后端语义见 `docs/DESIGN.md`；本文只讲视觉与交互规则，
> 以及这些规则落在哪些 token、哪个 CSS 类上。
> 依据：`Refactoring UI`（Adam Wathan / Steve Schoger）规则集，经
> `refactoring-ui-skill` 落地为可检查的约束。

## 1. 为什么要有这份文档

控制台第一版的取值是逐处挑的：19 种字号（含 11.5 / 12.3 / 12.6 / 12.8 / 13.6 / 13.8px）、
5 种字重（含 550 / 620 这种半档）、`var(--accent-dim)` 和 `var(--warn)` 两个**从未定义**的
CSS 变量（浏览器不报错，属性直接变成空值）。单看每一处都说得过去，合起来就是"没设计过"。

规则化的目的不是好看，而是**让下一次改动有唯一正确答案**：取值只能来自 token，越界即测试失败。

## 2. 四套尺度（唯一取值来源）

| 系统 | 取值 | 规则 |
|---|---|---|
| 字号 | `12 14 16 18 20 24` | §4.1.1d 手挑界面字阶；12px 是下限（§2.2） |
| 间距 | `4 8 12 16 24 32 48 64` | §3.2.2，16px 基数；相邻步长 ≥ 25%（§3.2.1） |
| 圆角 | 卡片 8 · 控件 6 · 胶囊 999 | §1.4.3 一种角色一档 |
| 阴影 | `--shadow-1/2/3`，X 偏移恒为 0 | §6.2.1 五档取三；§6.1.1 光来自上方 |
| 文字色 | `--text` / `--muted` / `--faint` | §2.2.a 三个层级，多一个即失败 |
| 字重 | 400 / 600 | §2.2.b 两档；正文不得低于 400 |

对应 CSS 变量：`--t-xs..2xl`、`--s-1..8`、`--radius*`、`--shadow-*`。

**页面里不写数字**：`style={{ fontSize: 13 }}` 这类按调用点挑值是被禁止的，
`tests/test_console_design.py` 会扫出来。需要新尺寸＝需要新 token，改一处而不是改十处。

## 3. 层级：每页只有一个"第一眼"

内容排序固定为三层，且每页只有一个第 1 层：

1. **操作员来取的那个数**——指标、模型状态、模型回答；
2. **会改变它的动作**——加载 / 启动 / 发送 / 保存；
3. **标签、单位、提示、时间戳、数据来源**。

落实手段：

- **标签降级而非加粗数值**（§2.5.3）：`.metric-label` 用 12px + `--muted` + 600，
  `.metric` 用 24/18px + `--text` + 600。三者同时降，数值自然浮起来。
- **每页一个实心按钮**（§2.8.a）：主操作 `.btn`；次要 `.btn.ghost`（描边）；
  三级 `.btn.link`。三档**性质不同**（填充/描边/文字），不是三种深浅。
- **危险操作按层级不按危险度着色**（§2.8.1）：页面上"删除/卸载"是安静的描边红，
  实心红（`.danger-solid`）只出现在确认面板里。
- **图标比文字淡一档**（§2.7.1）：图标覆盖面积比字形大，同色会压过文字。

## 4. 布局：按内容定宽，不按窗口

- 侧栏固定 216px（§3.4.1）。导航不因窗口变宽而变好，百分比宽度会同时造成"宽屏太空、窄屏折行"。
- 正文段落 `max-width: 35em`（§4.3，45–75 字符）。这个上限加在段落上，
  不加在列上（§4.3.1），所以代码块和表格仍可用满宽度。
- 设置项两列（§3.3.2）：输入框一列、说明文字一列，输入框不再被拉到 900px 宽。
- 分组间距 > 组内间距（§3.6）：设置项之间 `--s-5`，标签到输入框 `--s-1`。
- **宽表格在自己卡片里横向滚动**（`.table-wrap`），而不是把整页撑出横向滚动条——
  手机 390px 下模型页曾因此溢出 7px，是 P0。

## 5. 卡片与深度

- 卡片分离只用一个手段：**背景色差**（§8.5.2）。`--panel` 在 `--bg` 上已经足够，
  边框只负责锐化边缘，因此用很轻的 `--line`；没有一处在用"边框＋阴影＋背景差"三重分离。
- 阴影按 z 轴分配（§6.2）：卡片无阴影、控件 `--shadow-1`、浮层（图表 tooltip）`--shadow-2`、
  登录卡/确认弹层 `--shadow-3`。
- 按钮按下时阴影消失（§6.2.2），表达"压进页面"。
- 输入框是**凹陷**：顶部内阴影（§6.1.3），方向与凸起元素相反。

## 6. 昼夜主题

`data-theme` 挂在 `<html>` 上，React 渲染前由 `src/components/theme.ts` 写好，所以切页/刷新不闪。

深色不是浅色反相（§15）：

- **高度靠表面明度**，不靠阴影：`--bg < --panel < --panel-2 < --panel-3`，
  深色下阴影几乎不可见，不承载信息。测试断言了这个顺序。
- **主色反相**：白字压青底在深色面上到不了 4.5:1（原 `#f2fbf8` on `#2f8f7d` = 3.73:1），
  改为**亮青底 + 深墨字**（`#08110f` on `#4cc0a8` = 8.58:1）。这是 §5.6.1 的"翻转对比"。
- **饱和度不能只翻明度**，否则深色面会发灰。

## 7. 无障碍底线

- 焦点环全局统一 `:focus-visible` + `outline-offset: 2px`，偏移让它在自身填充色上也可见（§15）。
  没有任何一处 `outline: none` 不带替代——`tests/test_console_design.py` 逐处检查。
- `prefers-reduced-motion` 下动画与过渡全部关闭（§15）。
- 状态**不靠颜色单独表达**（§5.7）：每个 `.pill` 都同时有圆点和文字。
- 交互目标 ≥ 24px（§15）：导航行 36px、按钮 34/28px、复选框 16px 外留 4px。
- 对比度用 `web/acceptance/contrast_audit.py` 在真实 Chromium 里逐对测量，
  不是靠肉眼看（结果见 §9）。

## 8. 空状态

空状态是每个用户必然看到的状态，按 P0 处理（§8.4），因此都重写过：一句话说明"现在没有"，
再一句话说明"怎么让它有"，并指到具体页面/按钮。`.empty strong` 承担第一行，
避免整块灰字读成一段免责声明。

## 9. 度量结果（本轮，1440 / 1024 / 390，昼/夜）

| 指标 | 改前 | 改后 |
|---|---|---|
| 实际渲染字号种类 | 19 | 6（+ `--t-*` 全在尺度上） |
| 字重种类 | 5（400/550/600/620/700） | 2（400/600） |
| 未定义 CSS 变量 | 2（`--accent-dim`、`--warn`） | 0 |
| 卡内 `<h2>` 的 26px 上外边距 | 7 处 | 0 |
| 最宽正文块 | 109–116 字符 | 41–62 字符 |
| 横向溢出（390px） | 模型页 397 > 390 | 无 |
| 文字/背景对比度（WCAG AA） | 22/28 通过（深色主色 3.73:1） | 60/60 通过 |
| 空状态 | 纯灰字一行 | 结论 + 下一步 |

复现命令见 `web/acceptance/README.md`。

## 10. 边界

- 不改后端、API 语义、数据目录与 agent 行为；本分支只动 `web/`（源码 + 构建产物）、
  `web/acceptance/`、`tools/probe_console_readonly_proxy.py`、`tests/test_console_design.py`。
- 不引入框架、CDN、在线字体、图片下载；仍是手写 CSS + 系统字体，离线可用。
- 真实设备验证走只读代理（`tools/probe_console_readonly_proxy.py`）：
  只转发 GET/HEAD，唯一放行的写操作是 `POST /api/login`，所以在页面上点"加载/启动/保存"
  会被代理拦成 405，**不会到达板卡**。
