# Qwen3-VL-Embedding 验证记录（MYS-2846）

日期：2026-11-13。重启恢复后完成真机验收，推荐 **BF16、128/512/1024/2048 静态语言分档、官方 1310720 图片预算、四核**。
这是已测八个候选中的质量/性能选择，不代表穷尽全部优化或完整公开基准排名。
服务版本 0.6.35，PR [#140](https://github.com/zzttzzmyswy/cv84x6-llm-server/pull/140)。
sophon-demo sample 仅本地维护，不推送上游。服务模型需手工放入配套 bmodel/config，未上传模型仓库。

## 环境与方法

- 官方 `Qwen/Qwen3-VL-Embedding-2B`，revision `9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda`；
  `model.safetensors` 4,255,140,312 字节，SHA-256 `c73fa9caeddeb3ff831d46c085a7a5708343248ca777e90f2d486964464509c1`。
- TPU-MLIR `1.30.2-38`，目标 `bm1684x2`、四核；容器 image SHA-256
  `c0557edd68801aa3eb63ff0200475f4f9079e8f16017f684b533f6812bb201d9`。
- CV84X6 SoC，Ubuntu 22.04.5、kernel 5.10.4、libsophon 0.4.15；CPU RAM 约 2.3 GiB、NPU 26 GiB、VPP 2 GiB。
- 官方 FP32 参考为 PyTorch 2.11.0+cpu / Transformers 5.6.2；16 张 COCO val2017 图片、每图两条 caption、4 条图文、4 条文字边界，共 56 输入。
- 两种预算各 56/56 有效 token 与官方 processor 完全一致；保留 assistant 前缀后的 tokenizer EOS 151643。
  C++ 图像预处理另以官方融合归一化 golden 检查；不改变既有聊天图像路径。
- 质量门槛固定为每条 token 一致、2048 维有限单位向量、范数误差 ≤1e-5、余弦 ≥0.99。
  同时单独审查 MRL 双向 R@1，不以余弦通过代替检索评估。
- 各候选均单进程完成 56 输入；计时预热 2 次、重复 10 次。Python 总耗时含分词/图片预处理，不含模型加载。
  短文本为 38 token；低/原始预算图片为 256/322 token，图文为 274/340 token；长文本为 321 token。

三档为 128/512/2048；四档增加 1024。文件名量化级别指语言权重，ViT 沿用上游 converter 的浮点策略。
低预算 BF16 从动态改三档：短文本约 6.1 倍、图片约 1.7 倍加速。
W8 有单样本低于门槛，W4 最低余弦仅 0.6556，且图片速度无明显收益，均不作为质量默认。

原始预算 FP32 与低预算 FP32 的图片余弦最低 0.932823、平均 0.981697；
2048 维文字→图片 R@1 从 31/32 降至 30/32，图片→文字均为 16/16。这是缩图损失，不能归因于 NPU 量化。
因而默认保留原始图片预算。

## 最终模型效果

56/56 通过，最低余弦 0.99842048、平均 0.99950440，
最大范数误差 2.06e-08，token 差异为零。

| 维数 | FP32 文字→图片 | BF16 文字→图片 | FP32 / BF16 图片→文字 |
| ---: | ---: | ---: | ---: |
| 2048 | 31/32 | 31/32 | 16/16 / 16/16 |
| 1024 | 30/32 | 30/32 | 16/16 / 16/16 |
| 512 | 31/32 | 31/32 | 16/16 / 16/16 |
| 256 | 31/32 | 31/32 | 16/16 / 16/16 |
| 128 | 31/32 | 30/32 | 16/16 / 16/16 |
| 64 | 29/32 | 29/32 | 15/16 / 15/16 |

2048 维检索与 FP32 一致；128 维文字→图片有一条下降（31/32→30/32），不能声称所有 MRL 维数无损。
默认输出 2048 维；降低维数需按业务数据复验。此确定性小样本不能用于推断总体召回率差值。

## 分档与最大输入

额外 12 条 FP32 对拍：127/128/129、511/512/513、1023/1024/1025、2048 token，
5120 patch 最大面积图片（1280×1024，1302 token）及 2048-token 图文。

夹具由 sample 的 `tools/make_boundary_cases.py` 确定性生成。

| 513 | 1024 | 495.00 |
| 1023 | 1024 | 498.81 |
| 1024 | 1024 | 498.47 |

513 token 在旧三档要补至 2048，实测 2720.26 ms；新四档为 495.00 ms，约 5.50 倍加速。

## 故障记录与适用限制

最初第二次 W8 动态推理触发 `bmdrv_thread_sync_api` 120 秒超时及 `bdc_reg_read` 内核 oops，进程处于 D 态。
用户授权重启后恢复，本轮完整模型对比和最终 HTTP 卸载重载均未再复现。**原超时根因尚未确定，不能声称驱动问题已修复。**

本轮另发现读取 `/proc/bmtpu/bmdi_api_info` 会在 `otp_reg_read → bm1688_base_get_core_num/api_proc_show` 触发 oops；
这是诊断读取触发的独立现场，已再次重启恢复，后续避免该节点。最终验收 boot id 为
`a483288e-9a71-4b70-9348-b83863e45846`，每次推理后检查 dmesg，未发现 timeout/oops。
若设备再次出现此类错误，应停止追加 NPU 任务、保留日志并恢复板卡，不强杀在途 NPU 进程。
