# 精确尾部 K × 对齐 16 组合评测（10.42.0.242，Qwen3.6-35B-A3B 32k）

| 项目 | 内容 |
|---|---|
| **历史结论** | 「精确尾部 K × 对齐 16」四轮组合，**G1 第一条用例就打死 TPU**，因此没有通过率/首字数据；且 K=8 与 K=16 在 low 集上逐条等价 |
| **当前约束** | 该方向**停止**，不引入新的动态宽度，见 `docs/DESIGN.md` §3.3。这是 v0.6.5 选择「只补尾部、不改对齐」的直接原因 |
| **本篇保留** | 卡死现场、逐条推算的 `n / n%64 / L / 回放行数` 表——说明为什么这个组合不能做 |

MYS-2405，接 MYS-2403（`prefill-exact-tail-eval.md`，PR #24）。目标是找到一组
「精确尾部 K + 对齐 16」，同时做到：low 集 ≥ 39/40、mid 集 40/40、TTFT 中位数增加 ≤ 0.4 s。

**结论先行**

1. **G1–G4 四轮一个都没跑成：G1 的第一条用例就把 TPU 打死了。** 引擎加载模型成功
   （`load 63.1s`），G1 只走到 `--exact-tail 8` 的第一次预填充，120 s 后驱动报
   `bmdrv_thread_sync_api ... wait api timeout`，接着 `bdc_reg_read` 触发
   `Internal error: synchronous external abort`，第二次超时后内核打出
   `Fixing recursive fault but reboot is needed!`。按任务卡纪律**立即停止、未重试、未重启**。
   因此 G1–G4 的通过率、TTFT、失败用例**全部没有数据**，本阶段无法给出满足三条的组合判定。
2. **在 low 集上 `tail 8` 与 `tail 16` 完全等价，所以 G1 与 G3 是同一轮；但 mid 集上两者不同，
   G2 与 G4 仍然是两轮。** 机制是 `exact_from = n - K` 之后 `L` 向下取整到 16 的倍数，K 落在
   同一个 16 阶梯内时结果相同。逐条算过：
   - low 集：`K = 8…15` 全部产生**逐条完全相同的** `(L, 回放)`，因此 `K=8` 与 `K=16` 在 40 条上
     一字不差（`n=67` 两者都是 `L=48, 回放 19`）。**G1 ≡ G3。**
   - mid 集：`K=8` 的中位回放是 **18**，`K=16` 是 **20.5**，14/40 条路径不同。**G2 ≠ G4。**
   - 结论：四轮里有 3 个不同配置，不是 4 个。真正跨阶梯要取 `K = 7` 或 `K ≥ 17`
     （low 集最低回放：`K=7` 为 7 行、`K=8` 为 16 行、`K=17` 为 17 行）。
3. **`align 16` 下回放行数被压在 16–23 行（low 集），代价的上界可由已测数据直接估出来。**
   MYS-2403 在同一块板上实测「每补一行精确回放 ≈ 12.3 ms（短 prompt）/ 18.6 ms（128 token）」。
   low 集现状回放 0–7 行（中位 2）、候选回放 16–23 行（中位 18），即**中位多回放 16 行
   → 预估 +0.20…+0.30 s**，落在卡要求的 ≤ 0.4 s 以内；mid 集则是**少回放 32 行
   → 预估 −0.39…−0.60 s**（变快）。这是推算，**没有被本阶段的设备实测确认**。
4. **本阶段唯一可以交付的确定结论：这个方向在代价上可行，在收益上未知。** 正确率两条判据
   （low ≥ 39/40、mid 40/40）**一条都没有被验证**，必须在板子恢复后重跑才能给出。
   可直接复用的一点：`G1 ≡ G3`，所以恢复后**只需跑 3 个配置**（`low 16/t8`、`mid 16/t8`、
   `mid 16/t16`），不是 4 个。

## 逐条推算：n、n%64、L、回放行数

卡要求一张「n、n%64、实际预填充行数 L、回放行数、TTFT」表来验证「代价与回放行数成正比」。
**TTFT 一列没有实测值**（板子故障），L 与回放行数是按引擎 `Session::prefill_impl` 的算术算出来的：

```cpp
exact_from = n - min(n, max(0, exact_tail));
L = cur;  if (cur % al != 0)  L = (cur / al) * al;
if (c0 + L > exact_from)  L = max(0, (exact_from - c0) / al * al);
回放行数 = cur - L;
```

算式与代码逐行对应，`tools/prefill_row_probe.py::predict()` 是同一规则的独立实现，并由
`tests/test_prefill_row_probe.py` 用不变式（`L + 回放 == n`、`L % align == 0`、
`align 16 下回放 < 32`）钉住。**这些是推算，不是实测**；卡里要的「实测 L」需要在板子上
用 `LLM_TRACE=1` 数图发射次数才能得到，本阶段没做到。

## 关于任务卡的一点纠正建议

**G1 ≡ G3（在 low 集上 `tail 8` 与 `tail 16` 逐条相同），G2 ≠ G4。** 原因是 `L` 只认 16 的阶梯，
`K = 8…15` 落在同一阶梯内。四轮实际覆盖 **3 个不同配置**。若想在下一阶段真正测出 K 的影响，
应当取**跨阶梯**的值，例如 low 集上 `K ∈ {7, 8, 17, 19}` 分别给出最低回放
7 / 16 / 17 / 19 行。也就是说真正的分界点在 8（够 16 行）和 7（不够）之间，
继续比 8 与 16 是白跑一轮。
